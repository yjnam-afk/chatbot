# 프론트 UI 재설계 명세 — "시험장 책상 + 답안 서랍"

- 작성: 다인(디자인) / 확정 시안: B(시험장 책상) 뼈대 + A(토픽 서랍) 좌측 탭. C 제외.
- 목업: `docs/front-ui-mock.html` (독립 실행, 탭/도크 인터랙션 포함)
- 연계 스펙: `docs/answer-template-spec.md`(답안지), `docs/library-spec.md`(라이브러리·이벤트 연출)
- 원칙: **주인공은 답안지.** 5인 팀 보드·말풍선·팀 대화 피드 완전 제거. 이벤트 스키마는 무변경.

## 1. 화면 구성

```
┌────────────────────────────────────────────────────────────────────┐
│ header  🖋️ 기술사 답안 사무소        [모드 배지 LIVE/데모]           │
│         [ 문제 입력창……………………………………… ] [작성]                  │
│         [자동 판별|1교시형|2교시형]칩   ↳결과 메타 라인(작성 후)      │
├─────────────┬──────────────────────────────────────────────────────┤
│ rail 240px  │ stage (flex:1, 회색 책상 배경, 세로 스크롤)            │
│ ┌[진행][서랍]┐│                                                     │
│ │① 3단계    ││   ┌──────────────────────────┐                      │
│ │ 🔍 토픽검색││   │  답안지 .page (794px)     │ ← 줄 그리드 템플릿    │
│ │ 📄 조립    ││   │  머리행/문제 스트립/괘선   │   iframe srcdoc 렌더  │
│ │ ✅ 검증    ││   └──────────────────────────┘                      │
│ │② 분량게이지││   (2쪽, 3쪽 … 연속)                                  │
│ │③ 인쇄/PDF/ ││                                                     │
│ │  HTML/새탭 ││                                          ┌────────┐ │
│ └───────────┘│                                          │💬 대화  │ │
│              │                                  (접이식 도크, 우하단)│
└─────────────┴──────────────────────────────────────────────────────┘
```

- 입력은 **상단 입력창 하나로 통일**. 시험 문제(EXAM_WORDS 서버 판별)면 무대에 답안지,
  일반 질문이면 우측 하단 **대화 도크**에 답변이 온다. 입력창을 둘로 나누지 않는다.
- 초기 상태(답안지 없음): 무대에 빈 답안지 용지 + 워터마크 안내("문제를 입력하면 이 용지에
  답안이 채워집니다") + 예시 문제 3개 버튼. 서랍 탭은 초기에도 사용 가능.

## 2. 영역별 명세

### 2-1. 헤더 + 문제 입력

| 요소 | 내용 |
|---|---|
| 브랜드 | 🖋️ 로고칩 + "기술사 답안 사무소" + 서브 "문제를 붙여넣으면 답안지가 채워집니다" |
| 입력창 | 기존 `#chat-input` 재사용(이동). placeholder "문제를 입력하세요 · 예: SLA에 대하여 설명하시오 (25점)" |
| 버튼 | "작성" (accent). 스트리밍 중 disabled + "작성 중…" |
| 교시형 칩 | `[자동 판별|1교시형|2교시형]` 라디오 칩. 기본 자동. 수동 선택 시 요청 body에 `kind` 힌트 추가(서버 규칙 판별을 오버라이드) — 서버 협의 §5 |
| 결과 메타 라인 | reply 후 표시: `서술형 25점 · 라이브러리 적중 2건(SLA, SLM) · LLM 0콜 · 1.8초` — reply의 `library/matched/llm_calls` + 클라이언트 계측 시간. 폴백 경로면 `채점 91점 (보완 1회)` 형식(기존 문구 세트) |

### 2-2. 좌측 레일 — 탭 ①「진행」(기본)

**진행 3단계** (팀 보드 대체):

| 스텝 | 아이콘·이름 | 담당 에이전트(id) |
|---|---|---|
| 1 | 🔍 토픽 검색 | `orchestrator`, `nlu` |
| 2 | 📄 조립 | `designer`, `writer` |
| 3 | ✅ 검증 | `reviewer` |

스텝 카드 구조: 아이콘+이름 / 상태 칩(대기·진행 중·완료 ✓·오류) / 캡션 1줄(**다음 스텝이
시작되기 전까지의** 최신 talk 텍스트 — 이후 고정, §3 talk 규칙) / 완료 시
소요시간("0.4초", 클라이언트 계측).

**분량 게이지**: `⟨N⟩쪽 ⟨M⟩줄 / 목표 ⟨T⟩매` + 진행 바(`(22·(N−1)+M) / (22·T)`).
목표 T = 1교시형 1.4매, 2교시형 3.5매(방법론 상한). 데이터는 reply 확장 `sheet` 필드(§5),
없으면 iframe 문서 높이 ÷ (22×줄높이)로 근사.

**내보내기 버튼**: `🖨️ 인쇄`(primary, iframe.contentWindow.print()) / `PDF`(인쇄 다이얼로그와
동일 — 툴팁 "대상: PDF로 저장") / `HTML`(기존 downloadArtifact 재사용) / `새 탭`(blob URL).
답안지 없으면 전부 disabled.

### 2-3. 좌측 레일 — 탭 ②「토픽 서랍」(시안 A 요소)

- 데이터: `GET /api/library` → `index.json` 기반. **요구(§5)**: `topics` 맵 값에
  `name, category` 외 `mn`(두문자 word), `def`(35자 정의요약) 포함.
- 구성: 필터 입력(클라이언트 substring, name/mn/def 대상) → 분류 폴더 목록(category 1단계
  세그먼트로 그룹핑, 건수 표시, 클릭 시 펼침) → 토픽 카드 리스트.
- 토픽 카드: 토픽명 / 두문자 배지(앰버 톤) / 정의요약 1~2줄 / 액션 `[📝 1교시형] [📄 2교시형]`.
  액션 클릭 = 입력창에 `"{name}에 대하여 설명하시오 ({10|25}점)"` 채우고 **즉시 제출**
  → 진행 탭으로 자동 전환.
- 라이브러리 로드 실패/빈 응답: 탭에 "라이브러리 준비 중" 빈 상태 문구(기능 저하만, 오류 아님).

### 2-4. 무대(stage) — 답안지

- 배경: 책상 느낌의 중성 회색(`#e6e5e0`, 답안지 샘플 body와 동일) — 카드·장식 없음.
- 렌더: `artifact.html`(완결 HTML 문서)을 **`<iframe sandbox srcdoc>`**로 표시.
  iframe은 테두리 없음·투명 배경, 높이는 `onload` 후 내부 문서 scrollHeight로 맞춰
  **페이지 스크롤 하나로** 답안지 여러 쪽을 내리 읽게 한다(iframe 내부 스크롤 금지).
- 스트리밍 중: 용지 위에 옅은 오버레이 + 현재 스텝 캡션 미러("조립 중 — 2교시형 슬롯 배치…").
  reply 도착 시 오버레이 제거 + srcdoc 교체. 기존 자동 미리보기 모달은 제거(무대가 곧 미리보기).
- 초기/빈 상태: 빈 괘선 용지 1쪽(정적 마크업) + 중앙 안내 + 예시 문제 버튼 3개.

### 2-5. 대화 도크 (일반 질문)

- 위치: 우측 하단 고정 플로팅. 접힘 = `💬 대화` 필 버튼(+미읽음 뱃지), 펼침 = 340×420px 패널
  (헤더·메시지 리스트·독립 입력창 아님 — **입력은 상단 입력창 공용**, 패널 하단에는
  "질문은 위 입력창에 입력하세요" 힌트만).
- 동작: reply에 `artifact`가 **없으면** 일반 답변 → 도크에 말풍선 추가 + 도크 자동 펼침.
  `artifact`가 있으면 도크에는 요약 시스템 라인 1줄("📄 답안지 작성됨 — SLA (25점)")만 남겨
  이력 연속성 유지. 사용자 발화는 항상 도크 이력에도 기록.
- 기존 채팅 자산 재사용: `.msg.user/.msg.bot` 말풍선 스타일, history 배열(클라이언트 유지,
  30건 슬라이스) 그대로.

## 3. NDJSON 이벤트 → 진행 표시 매핑

에이전트 id ↔ 스텝: `{orchestrator:1, nlu:1, designer:2, writer:2, reviewer:3}` (§2-2 표).

| 이벤트 | 규칙 |
|---|---|
| 폼 제출 | 전 스텝 리셋(대기), 스텝1 활성, 타이머 t0 기록 |
| `agent` state `thinking\|working` | 해당 스텝 → 진행 중. `activity`(14자 이내)를 상태 칩에 표시. **앞 스텝이 진행 중이면 완료 처리**(done 이벤트 유실 대비). 이미 완료된 스텝이 다시 working이 되면 완료 해제 + 스텝에 "보완 n회" 카운터(폴백 경로의 보완 루프) |
| `agent` state `done` | 그 에이전트가 스텝의 마지막 담당(nlu/writer/reviewer)일 때 스텝 완료 + 소요시간 확정 |
| `agent` state `error` | 해당 스텝 오류 칩(red) + 캡션에 activity. 이후 스텝 대기 유지 |
| `talk` | 캡션을 그 텍스트로 교체(최신 1줄, 이력 없음). 단 **스텝은 "다음 스텝이 시작되는 순간" 캡션이 동결**되며(오류·reply 도착 시에도 동결), 동결된 스텝을 덮으려는 talk은 폐기한다. "완료 즉시"가 아닌 "다음 스텝 시작 시" 동결인 이유: 서버는 결과 요약 talk을 done 직후에 보낸다(예: nlu done → "라이브러리 1건 적중") — 완료 즉시 동결하면 보존해야 할 요약까지 버려진다. 이 기준이면 요약은 남고, 뒤늦게 도착하는 orchestrator의 마무리 인사("답안지 납품 완료!")만 폐기된다(정보 손실 방지, QA 판정 2026-07 — 완료 자체는 상태 칩 ✓와 reply가 표현하므로 무손실). 보완 루프로 스텝이 완료 해제되면 동결도 해제되어 갱신 재허용(위 행 규칙과 일관, 세아·다인 동의 2026-07) |
| `reply` (artifact 있음) | 전 스텝 완료 확정 → 무대 렌더, 게이지·메타 라인·내보내기 활성화 |
| `reply` (artifact 없음) | 스텝 리셋(대기 복귀), 답변은 도크로(§2-5) |
| 스트림 오류/중단 | 진행 중 스텝을 오류로, 도크에 오류 말풍선(기존 catch 로직 이전) |

`orchestrator working` 도 리셋 트리거로 겸용(office.js의 기존 리셋 규칙 계승) — 폼 제출과
중복되어도 무해(멱등).

## 4. 스타일 가이드

기존 토큰 전면 재사용 — 신규 색 도입 없음:
`--bg #f5f6f2 · --card #fff · --line #e7e9e2 · --accent #2f9e63 / dark #257f4f / soft #e7f5ec ·
--amber #f2b544 · --radius 18px · --shadow(기존)` / Pretendard.
무대 배경만 예외로 `#e6e5e0`(답안지 대비용, 답안지 샘플과 동일 값).

- 스텝 상태 칩: 대기 `#f0f1ec`/muted → 진행 중 accent-soft/accent-dark + 점멸 도트(기존
  blink 재사용) → 완료 accent-dark + ✓ → 오류 `#fdecec`/`#c2453e` (기존 칩 문법 그대로).
- 게이지 바: 기존 `.flow-fill` 그라디언트(accent→#6fc890) 재사용.
- 두문자 배지: `#fef3c7` bg / `#b45309` text (시안 A 계승, amber 계열).
- 답안지 용지는 웹앱 톤과 분리(명조·괘선) — 대비가 곧 "책상 위 종이" 연출이므로 웹앱
  토큰을 침투시키지 않는다.

## 5. 서버 협의 사항 (프론트 요구 — M2/M5에 반영 요청)

1. `reply` 확장: `sheet: {kind, points, pages, lines, target_pages}` — 조립기는 부품 줄 수
   합산으로 정확 산출 가능. 폴백 경로는 근사치 또는 생략(클라이언트 근사로 대체).
2. `index.json`의 `topics` 값에 `mn`(두문자 word), `def`(정의요약) 포함 (§2-3, 건당 ~60B).
3. 요청 body에 선택 필드 `kind: "1교시형"|"2교시형"` (칩 수동 선택 시 판별 오버라이드).
4. 일반 질문 reply는 기존대로 artifact 없음 — 추가 마커 불요(프론트는 artifact 유무로 분기).

## 7. 인터랙션 디테일

- 스텝 전환: 상태 칩 배경·색 200ms ease, 진행 중 도트 blink 0.9s(기존 값).
- 답안지 등장: srcdoc 교체 직후 iframe `opacity 0→1, translateY(6px)→0` 250ms — 종이를
  책상에 내려놓는 느낌. 과한 연출 금지(이 한 번만).
- 게이지: width transition 0.6s(기존 flow-fill 값).
- 서랍 카드 hover: `border-color: accent 55% mix` + shadow(기존 agent-card 활성 문법 재사용).
- 도크 펼침/접힘: height/opacity 200ms. 새 일반 답변 도착 시 접힘 상태면 뱃지 +1 & 1회 바운스.
- 예시 문제 버튼(빈 상태): 클릭 = 입력창 채움 + 제출.
- 키보드: `/` 입력창 포커스, `Ctrl+P` 답안지 있으면 인쇄 가로채기(iframe print).
