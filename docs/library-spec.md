# 토픽 라이브러리 스펙 — 사전 작성 부품으로 답안지 즉시 조립

작성: 누리(기획) / 발주 근거: "토픽별로 미리 작성해두면 어떤 질문이라도 적절히 섞어서 답안지
작성이 가능. 매번 생성하는 대기시간 제거."

## 1. 목표

토픽별 답안 부품을 레포에 정적 JSON으로 커밋해 두고, 문제가 오면 **무LLM 매칭 → 템플릿
조립**으로 라이브러리 적중 시 **LLM 0~1콜, 3초 이내**에 답안지를 전달한다. 미적중 토픽만
기존 라이브 파이프라인(최대 6콜)으로 폴백한다.

## 2. 요구사항

### 2-1. 토픽 모듈 데이터 모델

토픽 1개 = JSON 파일 1개. 씨앗은 발주자 드라이브의 두 자료:

- `경영전략_토픽.xlsx` (fileId `1chcuAItvweM-wOXj6CA8Zg4N_O33-SKR`): 166건,
  컬럼 = No / 토픽명 / 분류(트리 경로) / 키워드(암기) / 암기법 / 정의요약(35자) → **뼈대 필드 자동 생성**
- `MG_000_취합본_v1.3.pdf` (fileId `1cmTFbF4h3vqvQB9XW52Xo7nwW8Bb8-DU`): 토픽별 모범답안
  (MG_001_ITSM ~) → **본문 부품(개념도/표/활용)의 원천**, 반자동 추출+수작업 보정

스키마 (`api/_library/schema.md`에 동일 내용 유지):

```json
{
  "id": "MG-004",                         // 필수. "MG-" + xlsx No 3자리
  "name": "SLA",                          // 필수. 토픽명
  "aliases": ["Service Level Agreement", "서비스 수준 협약", "에스엘에이"],
                                          // 필수. 영문 풀네임/한글명/한글 음차. 매칭 전용
  "category": "MG > ITSM > SLA",          // 필수. xlsx 분류 그대로
  "keywords": ["SoW", "SLM", "SLO", "보상체계", "평가지표"],
                                          // 필수. xlsx 키워드(암기) 분해. 매칭 보조 + 답안 본문 소재
  "mnemonic": {"word": "기소카 메오메보", "expansion": ["기본계약서", "서비스 카탈로그", "..."]},
                                          // 필수. xlsx 암기법. 답안지 하단 암기 포인트 박스
  "definition": "IT서비스 제공자와 사용자 간 서비스 수준을 정량적으로 합의한 계약서",
                                          // 필수. 35자 요약 — 1교시형 서두/문제 재기술에 사용
  "definition_long": "…(2문장, 정의+목적)",  // 권장. 2교시형 서두
  "background": "…(등장배경/필요성 1~2문장)", // 선택
  "diagram_html": "<div class=\"diagram\">…</div>",
                                          // 선택. 개념도 — 인라인 CSS 박스/표만, 외부 리소스·<script> 금지
  "features": [{"item": "정량화", "desc": "..."}],            // 선택. 특징표(2단)
  "components": [{"name": "SLO", "role": "목표수준", "detail": "..."}],
                                          // 권장. 구성요소 3단표
  "comparisons": [{"vs": "MG-005", "vs_name": "SLM", "axes":
      [{"axis": "목적", "a": "수준 합의", "b": "수준 관리"}]}],
                                          // 선택. 인접 토픽 비교표 — vs는 토픽 id 참조
  "usage": ["활용방안/기대효과 …"],          // 선택
  "exam_points": ["기출 변형 포인트 …"],     // 선택. 문제 변형 대응 힌트 (조립 시 결론부 소재)
  "related": ["MG-003", "MG-005"]         // 선택. 복합 문제 연계 후보
}
```

- **필수 최소 셋**(뼈대): id, name, aliases, category, keywords, mnemonic, definition.
  xlsx만으로 166건 전부 자동 생성 가능해야 한다.
- **풀부품**: definition_long 이하. 없으면 조립기는 해당 섹션을 생략하거나(선택 섹션)
  LLM 1콜 보강(핵심 섹션)한다. 부품 유무가 조립을 깨면 안 된다.
- diagram_html 등 HTML 부품은 커밋 전 검증: `<script>`·외부 URL 포함 시 빌드 실패.

### 2-2. 저장 형식/위치 (Vercel 제약 대응)

- `api/_library/topics/MG-004.json` — 토픽당 1파일, 레포 커밋. `api/` 하위라 Vercel 파이썬
  함수 번들에 포함되고, `_` 접두사라 라우트로 노출되지 않는다 (기존 규칙 준수).
- `api/_library/index.json` — **빌드 산출물**(커밋). 정규화 역인덱스:
  `{"terms": {"정규화어": [{"id": "MG-004", "w": 10}, ...]}, "topics": {"MG-004": {"name": ..., "category": ...}}}`
- `scripts/build_index.py` — topics/*.json 스캔 → 스키마 검증(필수 필드, HTML 부품 금칙어)
  → index.json 재생성. 검증 실패 시 exit 1. 토픽 수정 커밋 전 반드시 실행.
- `scripts/seed_from_xlsx.py` — xlsx(CSV로 export한 파일 인자) → 뼈대 JSON 166건 생성.
  기존 파일에 풀부품이 있으면 뼈대 필드만 갱신(부품 보존 머지).
- 로딩: `api/_topic_library.py`가 **모듈 임포트 시점**에 index.json + topics/를 읽어 모듈
  전역에 둔다. 읽기 전용 정적 데이터의 콜드스타트 캐시이므로 "서버 인메모리 상태 금지"
  원칙(요청 간 가변 상태 금지)과 충돌하지 않는다. 쓰기 API는 만들지 않는다.
- 용량 가드: 전체 라이브러리 5MB 이하 유지(토픽당 평균 30KB). build_index가 총량 검사.

### 2-3. 질문 → 토픽 매칭 (무LLM 우선)

정규화 함수 `norm()`: 소문자화, 공백/괄호/특수문자 제거, 한글 초성열 추출(예: "제로트러스트"
→ "ㅈㄹㅌㄹㅅㅌ"), 영문 연속 대문자 약어 보존.

1. **인덱스 매칭 (LLM 0콜)** — 문제 텍스트를 norm 후 인덱스 term들과 대조. 점수:
   - name/alias 완전 포함: +10 (긴 term 우선, 겹치는 짧은 term은 흡수)
   - name 부분 일치(2자 이상): +5
   - keyword 일치: 개당 +1 (상한 +4)
   - 초성열 일치(4자 이상): +6
2. **확정 규칙**: 최고점 후보 score ≥ 8 → 적중. 복합 문제(2교시형) 대응: score ≥ 8 후보를
   **최대 3건**까지 채택(문제에 "비교", "관계", 나열 조사 존재 시 복수 채택 우선).
3. **모호 구간**(후보는 있으나 3 ≤ score < 8, 또는 상위 2건 동점): **LLM 1콜** —
   후보 id/name/definition 목록 + 문제 원문 → `{"ids": [...]} | {"ids": []}` JSON 선택.
   이때도 후보 목록 밖의 id는 채택 금지(환각 차단).
4. **미적중**(후보 없음 또는 LLM이 빈 배열): 기존 라이브 파이프라인 폴백(키 없으면 데모).
5. 일반 질문 분기: EXAM_WORDS 휴리스틱을 먼저 통과해야 매칭 시도. 비시험 문장은 기존
   chat 분기 그대로.

### 2-4. 조립 파이프라인 (적중 시 LLM 0~1콜, 목표 3초)

템플릿은 다인이 재설계 중인 `docs/answer-template-spec.md`(강정배 방법론 기반)를 따른다.
본 스펙은 **인터페이스만 고정**: 템플릿 = "섹션 슬롯의 순서 목록", 슬롯마다
`(슬롯명, 요구 부품 필드, 필수 여부)`. 기본 2종:

- 1교시형(용어형 10점): 정의 → 개념도(또는 특징표) → 구성요소표 → 활용/암기 포인트
- 2교시형(서술형 25점): 서두(정의+배경) → 개념도 → 구성요소표 → 비교표 → 활용/전망 → 암기 포인트

조립 규칙:

- 배점/유형 판별은 규칙 기반(문제의 `(N점)`, 어미) — LLM 0콜.
- 단일 토픽: 슬롯에 부품 1:1 배치. 선택 부품 부재 시 슬롯 생략.
- 복합 토픽(2~3건): 서두는 각 정의 병기, 본문은 토픽별 소단락, 비교표는
  `comparisons`에 상호 항목이 있으면 그것을, 없으면 두 토픽의 features를 축 정렬한
  자동 대비표를 사용. 암기 박스는 토픽별 병렬.
- 문제 맞춤 접합부(서두 1문장·결론부를 문제 어구에 맞게 다듬기):
  기본은 템플릿 문구 치환(0콜). 환경변수 `LIBRARY_POLISH=1`이고 키가 있을 때만 LLM 1콜.
- **부분 적중**(복합 중 일부 토픽만 미적중): 적중 부품은 조립하고, 미적중 토픽 소단락만
  로운 LLM 1콜로 생성 → 총 1~2콜 상한. 키 없으면 해당 소단락에 "라이브러리 미등록 토픽"
  플레이스홀더.
- 산출물은 기존 `artifact: {title, html}` 그대로. reply 이벤트 확장:
  `{..., "library": true|false, "matched": ["MG-004"], "llm_calls": n}`.

### 2-5. 프런트 에이전트 역할 재정의 (발주자 피드백 반영)

피드백: 현 역할 표기가 개발팀 복사판으로 보이고, '답안 구조 설계'는 작성과 중복, 간사는
하는 일이 없어 보임. 라이브러리 파이프라인의 **실제 코드 단계**와 1:1이 되도록 재정의한다.
id는 불변, 이름/역할 표기와 대사만 교체:

| id | 이름 | 역할 표기 | 실제 담당 (코드 단계) | LLM |
|---|---|---|---|---|
| `orchestrator` | 코디 | 접수 | 문제 접수, 배점·교시형 판별(`(N점)`/어미 규칙), 일반 질문 분기 | 0콜 |
| `nlu` | 누리 | 토픽 검색 | 인덱스 매칭, 적중/유사 토픽 판정, 모호 시 후보 선택 | 0~1콜 |
| `designer` | 다인 | 답안 편집 | 교시형 템플릿에 부품 배치·재단(슬롯 매핑, 분량·단락 조정) | 0콜 |
| `writer` | 로운 | 집필 | 접합부(서두·결론) 문제-맞춤 치환, 미적중 토픽 소단락 집필, 폴백 시 전체 집필 | 0~n콜 |
| `reviewer` | 세아 | 검증 | 형식 린트(필수 슬롯/표/암기박스/외부리소스 0건), 분량 점검, 폴백 시 채점 | 0~1콜 |

**5인 유지 판단**: 적중 시 3인으로 줄이는 안은 채택하지 않는다. 접합부 치환(코드가 실제
수행)을 로운의 상시 단계로 연출하면 5인 전원이 매 요청 실제 일을 가지며, 보드의 책상
5개 구조(office.js)를 경로별로 바꾸는 비용·혼란을 피한다. 대신 대사가 실제 작업량을
반영해야 한다 — 풀적중 시 로운은 "부품이 완전해서 연결부만 다듬었어요"처럼 가볍게.

**동기화 필수**: 역할 표기 변경 시 `api/_agents.py`의 `AGENTS`(role 필드)와
`api/_static/office.js`의 `DESKS`/`EMOJI`/`FLOW`를 반드시 함께 수정한다 (CLAUDE.md 규칙).
`/api/agents` 응답의 role이 프런트 표기의 단일 출처가 되도록 office.js가 하드코딩
role 문자열을 갖지 않게 정리한다.

### 2-6. 팀 보드 연출 (빠르게, 그러나 보이게)

이벤트 스키마(`agent`/`talk`/`reply`)와 에이전트 id는 무변경. 적중 경로의 고정 시나리오
(5인 전원 등장, 각자 실제 단계 수행 시점에):

1. 코디 `working "접수 중…"` → `talk "25점 2교시형 문제네요. 누리님, 토픽 검색!"`
2. 누리 `working "토픽 검색 중…"` → `talk "라이브러리 2건 적중: SLA, SLM"` (미적중분 있으면 언급)
3. 다인 `working "편집 중…"` → `talk "2교시형 슬롯 6개에 부품 배치했어요"`
4. 로운 `working "집필 중…"` → `talk` (풀적중: "연결부만 다듬었어요" / 부분적중: "미등록 토픽 1건 집필했어요")
5. 세아 `working "검증 중…"` → `talk "필수 섹션·암기박스 확인, 통과"` (규칙 검증, 0콜)
6. 코디 `done` → reply

이벤트 간 sleep은 **0.15초 이하**(연출용 최소치). 총 스트림 시간이 3초 목표를 깨지 않게 한다.
세아의 규칙 검증 항목: 필수 슬롯 존재 / 표 최소 2행 / 암기 박스 존재 / 외부 리소스 0건.
실패 항목은 reply 본문에 경고로 표기(조립은 그대로 전달).

## 3. 완료 기준 (curl 검증, 키 없이 `uvicorn api.index:app --port 8000`)

라이브러리 조립 경로는 LLM이 필요 없으므로 **키 없이도 데모가 아닌 실제 답안지**가 나와야 한다.

- [ ] `python scripts/seed_from_xlsx.py <csv>` 후 `ls api/_library/topics | wc -l` ≥ 166,
      `python scripts/build_index.py` exit 0
- [ ] `curl -s localhost:8000/api/library` → `.topics >= 166`, `.terms >= 500` (신규 통계 라우트)
- [ ] 단일 적중: `curl -s -X POST localhost:8000/api/chat -d '{"message":"SLA에 대하여 설명하시오 (25점)","history":[]}'`
      → 마지막 라인 `.library == true`, `.matched == ["MG-004"]`, `.llm_calls == 0`,
      `.artifact.html`에 SLA definition 문자열과 `"암기"` 포함, `.demo` 필드 없음
- [ ] 속도: 위 요청 `time curl` 총 소요 **3초 미만**
- [ ] 별칭/영문: `"Service Level Agreement를 설명하시오"`와 초성 별칭 입력 모두 MG-004 적중
- [ ] 복합: `"SLA와 SLM을 비교하여 설명하시오 (25점)"` → `.matched` 길이 2,
      artifact.html에 `<table>` 비교표와 두 토픽명 포함
- [ ] 미적중 폴백: `"양자내성암호에 대하여 설명하시오 (25점)"` → `.library == false`,
      기존 경로 수행(키 없으면 `.demo == true`)
- [ ] 일반 질문: `"기술사 공부는 어떻게 시작하나요?"` → artifact 없음, 매칭 시도 안 함
- [ ] 연출: 단일 적중 스트림에 5개 에이전트 전원의 `talk` 라인이 각 1건 이상 포함
- [ ] 역할 재정의: `curl -s localhost:8000/api/agents | jq -r '.agents[].role'` =
      정확히 `접수/토픽 검색/답안 편집/집필/검증` (id 순서 유지),
      `grep -c "기획자\|디자이너\|개발자\|QA" api/_static/office.js` = 0 (role 하드코딩 제거)
