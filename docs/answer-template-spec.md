## 1. 페이지 모델 (A4 · 줄 그리드)

> **v1.2 실물 공단(HRDK) 정정 (발주자 손답안 사진 2026-07-21)**: ①상단 머리행 폐지 —
> 실물 용지는 상단 표기가 없다. 페이지 = 본문 전용 **22줄**(1쪽만 문제 스트립 4줄 제외 18줄),
> 쪽 구분은 용지 밖 UI(쪽 네비). ②본문 가로 괘선은 **점선**(테두리·표는 실선).
> ③좌측 거터는 점선 세로줄로 구획된 **좁은 칸 2개** — 문N)·답)·단락 로마자(바깥 칸)·
> 가나(안쪽 칸)를 거터에 표기, 본문 열에는 제목 텍스트만. ④1교시 Ⅰ은 정의·특징
> 2열 박스(table.tdef — 정의 2줄 + 특징 1줄 원문자 나열). 아래 본문 표의 종전 수치
> (머리행 1+본문 17/21)는 이 정정으로 대체된다.

모든 배치의 단위는 실제 답안지의 **1줄**이다. CSS 변수 `--lh` 하나로 통제한다.

| 항목 | 값 | 근거 |
|---|---|---|
| 줄 단위 `--lh` | 화면 32px / 인쇄 10.5mm | 22줄 + 머리행이 A4 세로(297mm − 여백)에 정확히 수납 |
| 페이지당 줄 수 | **22줄** (머리행 1 + 본문 21) | 실물 국가시험 답안지 [실물], 발주자 확인. 방법론 문서에는 명시 없음 — 분량 규칙(1.2p, 3~3.5p)의 환산 기준으로 사용 |
| 페이지 구성 | 머리행(번호 칸 + "N 쪽"만 — 표제 없음) 1줄 + 괘선 본문 | [실물] 내지는 최소 인쇄, 체크리스트 U6 — "기술사답안지(제N교시형)" 표제는 임의 창작이라 제거 |
| 1쪽 특례 | 머리행 1 + **문제 스트립 4줄** + 본문 17줄 | 제품 요구(문제 원문·배점 상단 고정). 방법론상 문제는 "문 2) 요약"으로 첫 줄 기재 [1교시 31/65], [2교시 15/71] — 스트립의 `문 N) {title}`이 이 역할을 겸함 |
| 좌측 여백 | 본문 왼쪽 58px 거터 + **세로 3줄**(15px 간격 가이드선) | [공단] "왼쪽 여백에 단락 표기를 쉽게 하기 위해 세로로 3줄", 체크리스트 U3 |
| 괘선 | `repeating-linear-gradient`로 `--lh`마다 1px 수평선 | 외부 이미지 금지 요구 충족 |
| @page | `size: A4 portrait; margin: 12mm 14mm` | 22줄 × 10.5mm = 231mm ≤ 273mm 수납 확인 |

구현 골격:

```css
:root { --lh: 32px; }
@media print { :root { --lh: 10.5mm; } }
.body {
  height: calc(var(--body, 21) * var(--lh));   /* 1쪽만 --body:17 */
  background: repeating-linear-gradient(to bottom,
    transparent 0 calc(var(--lh) - 1px),
    var(--rule) calc(var(--lh) - 1px) var(--lh));
}
```

**줄 스냅 원칙**: `.content` 안 모든 요소는 `margin: 0`, `line-height: var(--lh)`,
높이는 `--lh`의 정수배만 허용. 여백이 필요하면 빈 `--lh` 배수 블록(`.gap`)으로만 만든다.

**글자 수 규칙 — 손글씨 기준 적용** (발주자 확정 2026-07-17, 종전 "비적용 선언" 폐기):
이 제품의 출력은 손으로 베껴 쓰는 연습 원본이므로 **화면 1줄 = 손글씨 1줄**이 되도록
내용 분량을 손글씨 용량에 맞춘다. 기준(공백 제외, 영문·숫자 반각 0.5자 환산 —
[실물] 기본 답안 2교시.pdf 줄바꿈 실측: 정의 줄바꿈 19/18자, 표 설명셀 9자/줄):
전폭 줄 **17~19자**, (정의)·마무리 2줄 문단 **38자**, 간글 **19자**,
3단표 구분열 3~4자·구성요소열 **5~7자**·설명열 한 줄 **~10자**(r2 합 20자).
초과는 서버 린터가 위반 처리한다(넘치면 위반 — 모자란 것보다 넘치는 게 죄).

## 3. 템플릿 자(Ruler) → CSS 칼럼 폭 환산

[자]의 자 마크: `구분` `개념` `비·비교` `2` `여` (+줄수 마크 5·6·9), 실측값 3 / 5.1 / 6 / 6.8 / 7.5 / 9.1cm.

**환산 기준**: 답안지 괘선 폭을 15.2cm로 두면 `비`(9.1cm)=60%가 되어 비교표의
"두 칸을 동일하게" [자] 규칙(20/40/40)과, 7.5cm=중앙선(≈50%)이 정확히 맞아떨어진다.
이 정합성을 근거로 15.2cm를 기준폭으로 채택한다(설계 판단 — 실물 자 미보유).

| 자 마크 | 실측 | CSS 위치(괘선 폭 대비) | 용도 |
|---|---|---|---|
| 구분 | 3.0cm | **20%** | 모든 표의 1열(구분 칸) 세로선 |
| 2 | 5.1cm | **34%** | 좁은 3단표의 2열 세로선 [자] |
| 여 | 6.0cm | **39%** | 2가지 설명 문제의 상세 구분선 [자] |
| 개념 | 6.8cm | **45%** | 개념도 표(1교시)의 개념 칸 [자] |
| (중앙) | 7.5cm | **50%** | 좌우 등분 보조선 |
| 비·비교 | 9.1cm | **60%** | 비교표 2·3열 등분선 [자] |

**단, 표 비율의 제1 기준은 방법론이다**: 3단표는 **2:2:6** [1교시 43/65 "표(2:2:6)"].
자 기반 20/14/66은 항목명이 짧은 표 전용 옵션으로 격하.

확정 CSS 클래스:

| 클래스 | 칼럼 폭 | 용도 | 근거 |
|---|---|---|---|
| `.t3` | 20% / 20% / 60% | 3단표(구분·구성요소/기술요소·설명). 9줄 상세표 포함 | [1교시 43/65] 2:2:6 |
| `.t2` | 20% / 80% | 2단표(필요성·기대효과 등) | [실물] ITSM 필요성 표, 구분선=자 '구분' |

| `.texp` | 20% / 19% / 61% | 2가지 설명 문제(정의2/개념도6/상세 N행) | [자] '구분'+'여' 기준 |

`table-layout: fixed` + 1행 셀 width로 고정. 셀 테두리는 잉크색 실선 —
음영 채움은 손답안에 없으므로 헤더에만 4% 미만의 옅은 틴트 허용.

| **IV. 로드맵 (기본)** | 물어본 가·나·다를 **하나의 그림** 6~7 + (정의) 2 + (필요성) 2 (10~12줄) | 요구사항 2개 이상 — Top-down, "이게 제일 좋음" | [2교시 42~48/71], 등장배경 3원+3단 구분선 [답안작성론 Intro] |
| V. 병렬식 | 서론 최소화, 물어본 것 그대로 목차 | 법·계산·문항 4개 이상 정답형 | [2교시 49/71] |
| VI. 발전단계 | 발전 순서·절차 그림/표 도입 | 단계·계보가 있는 토픽(GAN→DCGAN 등) | [2교시 50~53/71] |

샘플은 **Type IV**(문제가 검토 모델+구축 요건 2개 요구). 서론용 신규 클래스:
`.diagram.d7`(7줄), `.d-circle`(등장배경 원형), `.d-sep`(3단 구분 점선).
LLM 계약(§7) 허용 목록에 이 3개 추가.

## 6. 목차 번호·강조 서식

- 단락: `Ⅰ. Ⅱ. Ⅲ. Ⅳ.`(로마자), 하부: `가. 나. 다.`(h2마다 리셋) — 방법론 전체 사례 서식.
  구현: 번호는 **서버가 렌더 시 텍스트로 스탬프**(api/_agents.py `_stamp`) — CSS 카운터는
  페이지 분할(.content 다중화)에서 브라우저 카운터 스코프 결함이 확인되어 폐기(2026-07 검수).
  LLM·부품은 여전히 번호를 쓰지 않는다(§7 계약 무변경).
  아라비아(1. 1) (1)) 가이드는 "미준수 불이익 없음" [1교시 27/65]이므로 로마+가나다 유지.
- 키워드 강조는 **밑줄**과 **"쌍따옴표"** [1교시 24/65 "키워드 나열 – 밑줄, 쌍따옴표 1개 표기", 2교시 20/71].
  마크업은 `<u>`(권장). 기존 `.keyword` 클래스는 밑줄 스타일로 별칭 유지.
- 정의는 문장이 아니라 **키워드 나열** [1교시 24/65 "문장을 만들지 마세요"].
- 글꼴: 명조 serif 스택(본문·잉크색 청흑 #1c2f4a로 볼펜 느낌), 페이지 머리·문제 스트립은 sans(인쇄체 구분).
  외부 폰트/이미지/리소스 금지(제품 요구) — 손글씨 폰트는 도입하지 않음(가독성 우선, 발주 명세).

## 7. LLM(로운) 본문 프래그먼트 계약

LLM은 `{body}`로 **1쪽 괘선 안 내용만** 출력한다. 문제 스트립·머리행·"끝"·두문자는 템플릿/서버 몫.

```
[허용 태그·클래스 — 이 목록 밖 금지]
h2                     단락 제목 (번호 자동, 직접 "I." 쓰지 말 것)
h3                     하부 제목 (번호 자동, "가." 쓰지 말 것)
p class="ans"          첫 줄 "답)" 1회
p class="def"          2줄 문단(정의·특징·마무리 설명). 공백 포함 70자 이내
p class="gloss"        간글 1줄, "– "로 시작, 40자 이내
u                      키워드 밑줄(섹션당 1~3개), 강조 인용은 "쌍따옴표" 텍스트로
br                     줄바꿈 — 표 셀·d-box 내부 전용 (r2 행의 2줄 표기 등. 본 샘플도 사용)
table class="t3|t2|tcmp|texp" + thead/tbody/tr/th/td, 2줄 행은 tr class="r2"
div class="diagram"    개념도 6줄 컨테이너 (답안 전체 1~2개, 일도일표)
div class="diagram d7" 2교시 서론 로드맵 전용 7줄 컨테이너 (서론에 1개만)
  └ 내부 전용: div.d-row / div.d-col / div.d-box(+.soft: 점선 보조) /
               div.d-box.d-hub(중심 강조) / div.d-circle(등장배경 원형) /
               span.d-sep(3단 구분 점선) / span.d-arrow(→ ← ↓ ↔ 텍스트)
  └ 패턴 키트(docs/diagram-spec.md — 토픽 성격에 맞는 것 하나, 박스 일렬 나열 금지):
      d-flow(①흐름, 산출물은 d-out 칩) / d-tree(②계층: d-bar+d-stem+d-branch) /
      d-stack(③레이어) / d-cycle[.c6](④순환, 회귀 화살표 d-turn) /
      d-net(⑤허브 3×3) / d-vs(⑥비교대칭: d-zone×2+d-zt+d-link)
```

작성 규칙(시스템 프롬프트 수록용):
1. 용어형(10점) = §4 구성 그대로 / 서술형(25점) = §5 구성 그대로. h2에 빈 줄을 직접 넣지 말 것(CSS 자동).
2. 정의·설명은 키워드 나열형. **표 행 높이 = 내용 밀도 — 기준은 손글씨 캐파**(체크리스트 T5,
   발주자 규격. 타이핑본 기준 30~60자는 정정 폐기): 설명 칸 한 줄 ≈10자 → 셀 ≤10자면 1줄 행,
   ≈20자 또는 "- " 개조식 2항목(`<br>` 구분, 각 ≤9자)이면 `r2`. 가운데(구성요소) 칸 5~7자,
   정의 2줄 ≈36자, 전폭 한 줄 17~19자. 내용 1구절뿐인 r2 금지. 속성-설명형 셀은 "- " 개조식
   나열, 비교표(tcmp) 셀은 짧은 구 평문. 1열 카테고리가 하위 2~3행을 묶으면
   `<td rowspan>`(실물 구조 22~28% — 구조 근거는 타이핑본이어도 유효).
3. 서술형 II-나 상세표는 반드시 헤더1+행 조합 = 9줄(2줄 행 4개 또는 1줄 행 혼합 — 밀도 규칙 우선).
4. III(서술형)는 문제 지문의 요구사항 문구를 그대로 h3/표 헤더로 사용.
4-1. **간글(체크리스트 §6 확정)**: 본문 개념도 직후 `p.gloss` 1줄 필수. 서론 d7 뒤는 (정의)
   `p.def` 2줄이 간글을 대체. 표 뒤 간글은 선택(실물 <15%) — 남발 금지.
5. 개념도 예시 (6줄 컨테이너를 flex로 채움):

```html
<div class="diagram">
  <div class="d-col">
    <div class="d-box">평가·인증<small>eSCM · ISO 20000</small></div>
    <div class="d-box">서비스수준<small>SOW · SLA</small></div>
  </div>
  <span class="d-arrow">→</span>
  <div class="d-box d-hub">ITSM<small>고품질 IT 서비스 관리체계</small></div>
  <span class="d-arrow">←</span>
  <div class="d-col">
    <div class="d-box">품질인증<small>CMMI</small></div>
    <div class="d-box">Best Practice<small>ITIL</small></div>
  </div>
</div>
```

## 8. 현행 `_ANSWER_TEMPLATE`(api/_agents.py) 유지/폐기 지침

**유지 (그대로)**
- `render_answer()`의 단일 패스 `re.sub` 치환 + question/title/kind/points escape 처리
- placeholder 6개 계약 `{title} {kind} {points} {question} {body} {mnemonic_html}`
- h2 로마/h3 가나다 자동 번호 (구현은 CSS 카운터 → 서버 스탬프로 변경, §6)
- `.diagram / .d-row / .d-col / .d-box(.soft) / .d-arrow` 클래스 계약 (LLM 하위호환)
- `{mnemonic_html}` 계약(`<p><b>두문자</b> — 풀이</p>`)과 `_mnemonic_html()`
- serif 스택, `word-break: keep-all`, `print-color-adjust: exact`, A4 `@page`

**폐기 (줄 그리드로 대체)**
- `.sheet` 웹 문서형 단일 흐름 전체 → `.page`(머리행+괘선 본문) 구조
- 모든 자유 margin/padding (h2 26px, p 6px 등) → `line-height: var(--lh)` + 정수배 높이
- `.q-box` 틴트 박스 → 1쪽 문제 스트립(4줄)
- h2 `border-bottom`, th 배경 틴트(→4% 이하), `.d-title`(간글로 대체), `.d-box.wide`(d-col/그리드로 대체)
- `.answer min-height: 280px` → 줄 수 기반 페이지 높이
- `.mnemonic` 위치는 유지하되 3줄 높이 고정 + "끝" 뒤

**신규**
- `--lh` 줄 그리드, 괘선 gradient, 좌측 번호 거터, 페이지 머리행, `.t3/.t2/.tcmp/.texp` 칼럼 규격,
  `tr.r2`, `.ans/.def/.gloss/.end/.gap`, `.d-hub`, 2교시형 단락 여백 `.p2 h2 { margin-top: var(--lh) }`
- `render_answer()`에 kind에 따라 content 래퍼 클래스 `p1|p2` 부여 (단락 여백 스위치)

**페이지 분할 구현 선택지 — v2 채택 (발주자 3차 반려 2026-07 반영)**
- ~~v1: 연속 괘선 본문 하나 + 인쇄는 브라우저 분할~~ — "쪽 개념이 없어 템플릿을 안 지킨
  것처럼 보인다"는 반려로 폐기.
- **v2(샘플 방식, 현행)**: 서버가 본문 블록별 줄 수(§2 규칙)를 계측해 22줄 고정 `.page`로
  직접 분할(`_layout`, api/_agents.py) — 쪽별 머리행("N 쪽"), 문제 스트립은 1쪽만, h2/h3
  목차 번호는 서버가 텍스트로 스탬프(§6 — CSS 카운터·페이지 시드 폐기). 2교시형 단락
  여백은 명시적 `.gap` 블록으로 물질화(페이지 첫 줄이면 생략). 화면 쪽수 = 인쇄 쪽수 =
  reply `sheet.pages`. 유의: 라이브러리 부품은 줄 수가 정확하나 LLM 폴백 본문은 규칙 위반
  (셀 초과 길이 등) 시 계측 오차 → 페이지 `overflow: hidden`으로 그리드는 지키되 잘림 가능.

## 9. 검증 메모 (코디 기파악 내용 대비)

- "개념도 = 항상 6줄" — 방법론 원문은 "6줄 평균(5~7줄)" [1교시 42/65]. v1은 6줄 고정 채택(그리드 단순화).
- "2 = 5.1cm, 여 = 6cm" — [자] 원문 순서상 매핑 확정 불가하나 채택. 단 3단표 비율은 2:2:6이 방법론 명시라 우선.
- "페이지당 22줄" — 방법론 문서에 직접 명시 없음. 실물 스캔·발주자 확인 기반. 모든 분량 규칙과 정합.
- 추가 반영: 단락 빈 줄은 **2교시형 전용** [2교시 54/71] — 1교시형에 넣으면 오히려 방법론 위반.
- **서론 반려 반영(2차)**: 실물 스캔(기본 답안 2교시.pdf)의 "가.정의 + 나.필요성 표" 서론은
  Type I 형태의 구버전 수강생 답안 — V5.0 표준 서론은 **그림 서론**이며 기본은 Type IV 로드맵
  ("이게 제일 좋음" [2교시 42/71], 6~7줄 그림 + 정의 2줄 + 필요성 2줄 [2교시 43/71],
  등장배경 3원+3단 구분선 [답안작성론 Intro]). 샘플 1단락을 Type IV로 교체, 6타입 표는 §5.
  1교시형 서론(가.정의 2줄 + 나.특징)은 1교시 방법론 그대로라 무변경.
